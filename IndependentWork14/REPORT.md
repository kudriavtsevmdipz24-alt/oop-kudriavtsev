# Звіт до Самостійної роботи №14: Вивчення Dictionary<TKey, TValue> та HashSet<T> у бібліотеках .NET

## Частина 1. Аналіз використання у відкритих проєктах (Open-Source)

### 1. Використання `Dictionary<TKey, TValue>` — Dapper
* **Репозиторій та файл:** [Dapper / SqlMapper.cs](https://github.com/DapperLib/Dapper/blob/main/Dapper/SqlMapper.cs) (внутрішній кеш запитів `_queryCache`).
* **Контекст:** Dapper кешує скомпільовані делегати мапінгу SQL-результатів у C#-об'єкти за унікальним ключем `Identity` (комбінація SQL-рядка, типу підключення та типів параметрів).
* **Чому обрано `Dictionary`:** При виконанні тисяч SQL-запитів на секунду критично важливо миттєво знаходити вже згенерований десеріалізатор. Лінійний пошук у `List` ($O(N)$) створив би вузьке місце.
* **Складність операцій:** $O(1)$ в середньому для пошуку (`TryGetValue`) та додавання.
* **Особливі вимоги:** Використовується спеціалізована структура ключа `Identity` з перевизначеними `GetHashCode()` та `Equals()` для швидкого порівняння без алокації пам'яті.

### 2. Використання `HashSet<T>` — Newtonsoft.Json
* **Репозиторій та файл:** [Newtonsoft.Json / JsonSerializerInternalWriter.cs](https://github.com/JamesNK/Newtonsoft.Json/blob/master/Src/Newtonsoft.Json/Serialization/JsonSerializerInternalWriter.cs) (колекція `_serializeStack`).
* **Контекст:** Відстеження об'єктів, які зараз знаходяться у стеку серіалізації, для виявлення циклічних посилань (`ReferenceLoopHandling`).
* **Чому обрано `HashSet<T>`:** Перед серіалізацією кожного вкладеного об'єкта потрібно перевірити, чи не зустрічався він вище по дереву. `HashSet.Add()` одночасно перевіряє наявність і додає елемент за константний час.
* **Складність операцій:** $O(1)$ для `Add`, `Remove` та `Contains`.
* **Особливі вимоги:** Використовується порівняння за посиланням (`ReferenceEqualityComparer`), щоб два різні екземпляри об'єктів з однаковими полями не вважалися циклічним посиланням.

### 3. Комбіноване використання `Dictionary<TKey, HashSet<T>>` — .NET Runtime (`System.Diagnostics.DiagnosticSource`)
* **Репозиторій та файл:** [dotnet/runtime / DiagnosticListener.cs](https://github.com/dotnet/runtime/blob/main/src/libraries/System.Diagnostics.DiagnosticSource/src/System/Diagnostics/DiagnosticListener.cs).
* **Контекст:** Збереження підписників на діагностичні події за назвою події.
* **Чому обрано комбінацію:** `Dictionary` миттєво знаходить групу підписників за назвою події ($O(1)$), а `HashSet` гарантує, що один і той самий слухач не буде підписаний двічі на одну подію.

## Частина 2. Порівняльна таблиця складності операцій

| Операція | `List<T>` | `Dictionary<TKey, TValue>` | `HashSet<T>` | Коли використовувати |
| :--- | :---: | :---: | :---: | :--- |
| **Додавання** | $O(1)$* | $O(1)$* | $O(1)$* | `List` — коли важливий порядок індексів; хеш-колекції — для швидкого доступу. |
| **Пошук за значенням** | $O(N)$ | $O(N)$ (`ContainsValue`) | $O(1)$ | `HashSet` ідеальний для перевірки належності до множини унікальних значень. |
| **Пошук за ключем** | N/A | $O(1)$ | N/A | `Dictionary` — стандарт для асоціативних масивів «Ключ $\rightarrow$ Значення». |
| **Видалення** | $O(N)$ | $O(1)$ | $O(1)$ | `List` вимагає зсуву елементів масиву; `Dictionary`/`HashSet` видаляють за хешем. |
| **Перевірка наявності** | $O(N)$ | $O(1)$ (`ContainsKey`) | $O(1)$ (`Contains`) | Завжди замінювати `List.Contains` на `HashSet`/`Dictionary` на великих обсягах. |

*\*Амортизований час $O(1)$; у найгіршому випадку при розширенні внутрішнього масиву (rehash/resize) — $O(N)$.*

## Частина 3. Висновки про вибір колекції
* **Коли `Dictionary` краще за `List`:** Коли дані мають унікальний ідентифікатор (ID, ім'я файлу, код товару) і основною операцією є пошук, оновлення або видалення за цим ключем.
* **Коли `HashSet` є оптимальним вибором:** Коли потрібно зберігати лише унікальні елементи без дублікатів, миттєво перевіряти наявність елемента або виконувати математичні операції над множинами (`UnionWith`, `IntersectWith`, `ExceptWith`).
* **Підводні камені при використанні:**
  1. Зміна полів змінюваного (mutable) об'єкта-ключа після додавання в `Dictionary` або `HashSet` змінює його `GetHashCode()`, через що об'єкт стає неможливо знайти в колекції.
  2. Невідповідність `Equals` та `GetHashCode` у власному `IEqualityComparer<T>` призводить до появи дублікатів або втрати елементів.
  3. Хеш-таблиці споживають більше оперативної пам'яті, ніж компактний масив усередині `List<T>`, і не гарантують збереження порядку сортування.
